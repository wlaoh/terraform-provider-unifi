# Firewall Policy Ordering (Resource)

Manage the complete order of user-defined firewall policies for one source/destination zone pair using the Integration API and an API key. Import the existing order first. Use Integration API UUIDs for policies and zones; legacy controller IDs from the firewall policy resource use a different namespace. Supply every current user policy exactly once across the two lists. Removing this resource releases ownership and leaves the controller order in place.

## Example Usage

```terraform
# Use the UUIDs returned by the Integration API for this site and zone pair.
resource "unifi_firewall_policy_ordering" "internal_gateway" {
  site_id             = var.integration_site_uuid
  source_zone_id      = var.internal_zone_uuid
  destination_zone_id = var.gateway_zone_uuid
  before_system_defined_policy_ids = [
    var.allow_iot_echo_policy_uuid,
    var.block_other_iot_gateway_policy_uuid,
  ]
  after_system_defined_policy_ids = []
}
```

## Schema

### Required

- `after_system_defined_policy_ids` (List of String) User policies evaluated after system-defined policies, in evaluation order.
- `before_system_defined_policy_ids` (List of String) User policies evaluated before system-defined policies, in evaluation order.
- `destination_zone_id` (String) Destination zone Integration API UUID.
- `site_id` (String) Integration API site UUID.
- `source_zone_id` (String) Source zone Integration API UUID.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

